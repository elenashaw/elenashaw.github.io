File Naming Conventions

Naming

Files Created by Myself

  • Use the general format: Name1-Name2-Name3-Suffix

  • e.g.

    bash Computer-Vision-Note

  • If there are widely accepted abbreviations, they can be used. Abbreviations with unclear meaning are not allowed.

  • e.g.

    • CS for Computer Science: allowed
    • PaS for Probability and Statistics: prohibited

  • Prepositions should not be capitalized.

Forked Files

  • Keep the original file names as they are.

Suffix naming

  • Note: Notes file
  • AINote: Notes primarily generated by AI
  • Project: Engineering or project code files
  • Practice: Homework exercises or tutorial practice
  • Reimplement: Reimplementation of papers or projects
  • MyLib: Materials mainly collected or translated from external sources (not original work)

Separator

Repository Names

  • - is preferred as the separator.
  • _ can be used as a secondary option.
  • I or l may be used as compound suffix separators only in private repositories.
  • e.g.: Stoa-NoteIMyLib
